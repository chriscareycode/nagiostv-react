# July 26, 2026 Follow-up Refactoring Checklist

This document records findings from a read-only follow-up review performed
after completing all items in `notes/2026-07-REFACTOR.md`. The project has a
strong validation baseline, but several small correctness and maintainability
improvements remain.

Items are ordered roughly by expected correctness value and implementation
effort.

## Priority 1: Alert filtering correctness

- [x] Use the filtered alert list when calculating adjacent alert timestamps in
  `src/components/alerts/AlertItems.tsx`.
  - Rendered entries come from `trimmedItems`, but `prevtime` currently comes
    from the unfiltered `items` array.
  - After searching or hiding soft alerts, the two array indexes may no longer
    refer to adjacent rendered alerts.
  - This can display an incorrect quiet period between alert entries.

- [x] Use the filtered alert list for the initial quiet-period display.
  - The initial `QuietFor` currently uses `items[0]`, even if the newest alert is
    excluded by the search or soft-alert filter.
  - Hide the display when the filtered list has no suitable entry.

- [x] Base alert pagination controls on the filtered result count.
  - The "show more" condition currently uses `items.length`.
  - A search with only a few matches can therefore display a button that does
    not reveal any additional entries.
  - Add focused `AlertItems` tests covering search filtering, hidden soft
    alerts, quiet-period timestamps, and show-more/show-less behavior.

## Priority 2: Validate settings from URLs

- [x] Parse URL setting overrides through a typed allowlist in
  `src/components/SettingsLoad.tsx`.
  - The current loader accepts arbitrary query-string keys and spreads them
    directly into `ClientSettings`.
  - It converts literal `true` and `false`, but all numeric settings remain
    strings at runtime.
  - Unknown keys and invalid values should be ignored rather than added to the
    settings object.
  - Parse each supported setting according to its declared type.

- [x] Enforce safe ranges for numeric settings.
  - Polling frequencies should respect the existing minimum polling interval.
  - Alert history ranges, item limits, version-check intervals, and similar
    settings should reject non-finite and out-of-range values.
  - Add tests for valid typed overrides, unknown keys, malformed numbers, and
    conflicting search/hash parameters.

- [x] Use a sanitized request timeout rather than
  `(fetchFrequency - 2) * 1000`.
  - The current calculation appears in host, service, and alert requests.
  - Invalid or very small values supplied through persisted, remote, or URL
    settings can produce zero, negative, or otherwise inappropriate timeouts.
  - Keep the timeout calculation consistent with the polling interval
    sanitization in `useCancellablePolling`.

## Priority 3: Version-check retry behavior

- [x] Record a version check as completed only after a successful response.
  - `useVersionCheck` currently updates the in-session and persisted check
    timestamps before making the HTTP request.
  - A temporary network or server error then suppresses additional attempts for
    approximately 23 hours.
  - Persist the successful timestamp in the success path.
  - If needed, use a shorter in-session failure backoff to avoid rapid retries.
  - Add a regression test proving that a failed request remains eligible for a
    later retry.

## Priority 4: Expand static-analysis coverage

- [x] Enable an appropriate TypeScript ESLint recommended ruleset.
  - The current ESLint configuration primarily validates the two React Hooks
    rules.
  - It does not flag many common issues such as explicit `any`, unused values,
    suspicious expressions, or unsafe promise handling.
  - Start with the non-type-aware recommended rules and resolve the resulting
    focused backlog.
  - Evaluate type-aware rules separately because they may create a larger
    migration.

- [x] Replace avoidable `any` types in shared request helpers.
  - `getJson` defaults its response type to `any`.
  - `handleFetchFail` accepts and updates untyped atom state.
  - Introduce a small error-state interface or generic constraint so the helper
    preserves atom state types.

## Priority 5: Dependency and console hygiene

- [x] Remove `@types/jquery` if a final repository-wide check confirms it is
  unused.
  - Neither `jquery` nor its types are referenced under `src/`.

- [x] Move `@types/qs` from runtime dependencies to development dependencies.
  - It is compile-time-only metadata and is not required by the production
    application.

- [x] Review unconditional console output in normal application paths.
  - Remove obsolete event-handler and chart diagnostics.
  - Gate useful diagnostics behind the existing debug mode.
  - Avoid logging full LLM messages or prompts by default because monitoring
    data may be sensitive.
  - Preserve actionable error reporting where the console is the only useful
    diagnostic channel.

- [x] Run live dependency freshness and vulnerability checks in a
  network-enabled environment.
  - `npm outdated`
  - `npm audit --omit=dev`
  - The July 26 live review found a high-severity direct Axios advisory, a
    low-severity transitive Babel advisory, and two moderate React Router
    advisories.
  - Updated Axios from 1.16.0 to 1.18.1 and allowed the non-breaking audit fix
    to update Babel from 7.28.5 to 7.29.7.
  - A repeated production audit confirmed that no high- or low-severity
    production advisories remain.
  - Several dependencies have newer major releases. Do not combine those
    migrations into routine patch updates.

- [ ] Migrate React Router from v6 to v7 and verify navigation behavior.
  - The remaining production audit findings are two moderate React Router
    advisories: `GHSA-wrjc-x8rr-h8h6` and `GHSA-337j-9hxr-rhxg`.
  - npm has no patched v6 release and proposes `react-router-dom@7.18.1`.
  - Treat this as a deliberate breaking migration; do not use
    `npm audit fix --force`.
  - Verify `HashRouter`, route-level lazy loading, query parameter handling,
    settings/help/update navigation, and direct hash URLs.
